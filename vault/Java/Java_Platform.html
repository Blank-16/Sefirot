Java Platform Architecture

The Java platform provides a high-performance, object-oriented runtime environment designed around portable bytecode executed by the Java Virtual Machine (JVM). Its layered architecture isolates application logic from host operating systems while maintaining strict type safety and automatic memory management.

1. JVM Runtime Structure

  • Classloader Subsystem: Loads, links, and initializes bytecode files (.class) through delegation hierarchies (Bootstrap, Extension/Platform, Application).
  • JVM Memory Layout:
    • Heap: Shared storage for all instantiated objects and instance variables; managed by the Garbage Collector.
    • Metaspace: Off-heap native memory storing class metadata, method descriptors, and constant pools.
    • JVM Stacks: Thread-confined frames storing primitive local variables, object references, and partial method call results.
    • Program Counter (PC) Registers: Contains the address of the JVM instruction currently being executed per thread.
  • Execution Engine: Combines bytecode interpretation with Just-In-Time (JIT) compilation (C1 client compiler for quick startup, C2 server compiler for peak performance profile optimization).

2. Garbage Collection & Memory Management

  • Generational Hypothesis: Most objects become unreachable shortly after allocation; memory is partitioned into Young (Eden, Survivor spaces) and Tenured (Old) generations.
  • G1 GC (Garbage-First): Default general-purpose collector. Divides heap into uniform regions; collects regions with the highest amount of garbage first within a target pause time.
  • ZGC (Z Garbage Collector): Ultra-low latency collector with pause times consistently below 1 millisecond regardless of heap size, utilizing colored pointers and load barriers.

3. Modern Language Features (Java 17 & 21 LTS)

  • Records: Immutable, compact data carrier classes with compiler-generated accessors, equals(), hashCode(), and toString().
  • Pattern Matching: Enhanced instanceof and pattern-matching switch expressions eliminating explicit type casting.
  • Sealed Classes: Explicit control over inheritance by declaring permitted subclasses via sealed ... permits.
  • Virtual Threads (Project Loom): Lightweight threads managed directly by the JVM runtime rather than 1:1 OS kernel threads, scaling concurrent throughput for I/O-bound applications.
